# Git Workflow

이 문서는 Re:write 프론트엔드의 커밋, PR, Codex 협업 규칙을 정의한다.

코드 작성 규칙은 `docs/CONVENTIONS.md`를 따른다.

## 1. Commit Convention

커밋 메시지는 다음 형식을 사용한다.

```txt
<emoji> <Type>: <summary>
```

예시:

```txt
🔧 Chore: eslint와 prettier 설정 추가
📝 Docs: 아키텍처 문서 추가
✨ Feat: 자기소개서 목록 페이지 추가
```

현재 commitlint 설정에서 허용하는 타입은 다음과 같다.

```txt
✨ Feat
🐛 Fix
♻️ Refactor
🔧 Chore
🎨 Style
📝 Docs
🚚 Rename
🔥 Remove
```

## 2. Commit Type

| 타입 | 사용 시점 |
|---|---|
| `🎉 Init` | 프로젝트 생성, 최초 초기화 |
| `✨ Feat` | 새로운 기능 또는 페이지 추가 |
| `🐛 Fix` | 버그 수정 |
| `♻️ Refactor` | 동작 변경 없는 코드 리팩토링 |
| `🔧 Chore` | 설정, 빌드, 패키지, 아이콘, 이미지 추가 |
| `🎨 Style` | 스타일 또는 포맷팅 변경 |
| `📝 Docs` | 문서 또는 주석 수정 |
| `🚚 Rename` | 파일 또는 디렉토리명 변경, 파일 이동 |
| `🔥 Remove` | 코드 또는 파일 삭제 |

## 3. Commit Body Rule

커밋 제목만으로 설명이 부족할 때 본문을 사용한다.

- 제목과 본문은 빈 행으로 분리한다.
- 본문은 한 줄 최대 72자로 작성한다.
- 본문은 한글로 작성한다.
- 본문에는 어떻게보다 무엇을 왜 변경했는지 작성한다.

예시:

```txt
📝 Docs: 아키텍처 문서 추가

PRD 이후 구현 기준을 맞추기 위해 레이어 책임과 라우트 구조를
문서화했습니다. 현재 폴더 구조와 ESLint boundaries 설정을 기준으로
작성했습니다.
```

## 4. PR Policy

PR은 `.github/PULL_REQUEST_TEMPLATE.md` 형식을 따른다.

PR 본문에는 다음 내용을 포함한다.

- 연관된 이슈
- 체크 사항
- 작업 내용
- 스크린샷 또는 참고 이미지
- 추가한 라이브러리
- 리뷰 요구사항

문서 변경만 있는 PR은 스크린샷과 추가 라이브러리를 생략할 수 있다.

## 5. Codex Git Policy

Codex는 커밋 메시지와 PR 본문 초안을 작성할 수 있다.

Codex는 사용자가 명시적으로 요청하지 않는 한 다음 작업을 실행하지 않는다.

- `git commit`
- `git push`
- PR 생성

사용자는 Codex가 작성한 커밋 메시지와 PR 본문 초안을 검토한 뒤 직접 커밋, 푸시, PR 생성을 수행한다.
